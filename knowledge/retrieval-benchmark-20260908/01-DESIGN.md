# 300문항 로컬 검색 벤치마크 설계

## 범위와 기록

사용자 요청: 300문항 수행, 모든 결과와 작업 내역의 문서화, 별도 최종 검수 문서. 기존 feature/policy-knowledge-corpus에서 이어간다. 정책 원문·발췌·146청크 및 기존 Chroma는 보존한다. 보고서와 데이터는 knowledge/retrieval-benchmark-20260908/에 둔다. 대형 벡터 캐시는 reports/에 둔다. commit/push/PR/merge는 이번 요청에 포함하지 않는다.

## 데이터

- 150개 시나리오 × 표현 2개 = 300문항. 서로 다른 300개 독립 업무 시나리오라고 주장하지 않는다.
- 기본 100, 조건·예외 100, 복합 정책 40, 답 없음·정보 부족 30, 개인 상태·무관 질문 30.
- 같은 시나리오의 표현 변형은 같은 split에 둔다. 개선용 200, 최종용 100. 최종용은 질문 작성·근거 검수에는 접근하지만 개선 라운드의 점수·실패 분석에는 사용하지 않는다. 독립된 사람의 블라인드 검수라고 부르지 않는다.
- gold는 정책 ID와 발췌 원문의 구절·출처 줄 범위로 고정한다. 정책 원문을 바꾸거나 합성 정답을 검색 문서에 넣지 않는다. 원문 근거가 없는 질문은 필요한 처리 유형을 지정한다.
- 질문·근거 검수 완료 후 SHA-256을 고정한다. 실험 이후 수정 필요 시 이전본과 수정 이유를 보존하고 결과를 새 버전으로 구분한다.

## 최대 5라운드

1. R1: 현재 본문 임베딩 cosine 상위5/0.70 기준선.
2. R2: 같은 검색 순위 + 정책 단위 원문 확장. 검색된 정책별 최대3개, 전체 문맥 최대6000 E5 토큰. 예산에서 잘린 범위를 기록한다.
3. R3: 본문 dense + 원문 제목/본문의 BM25를 RRF(k=60)로 결합 + 동일 정책 확장.
4. R4: R3 상위20 후보를 제목 포함 E5 임베딩 유사도로 재정렬 + 동일 정책 확장. CrossEncoder와 동일한 실험이라고 부르지 않는다. 별도 신경망 reranker는 이번 라운드에서 설치하지 않는다.
5. R5: 개선용 결과로 선택을 고정한 뒤 기준선과 선택 방식만 최종100문항에서 비교. 최종 점수를 보고 재튜닝하지 않는다.

선택 기준: answerable 문항의 모든 gold 구절 포함 비율 우선, 다음 정책 recall, 다음 문맥 토큰 비용. 검색 후보 수·정책 확장 예산을 명시해 문맥 증가에 의한 효과와 순위 개선을 구별한다. 점수만으로 원문 없는 질문을 차단할 수 있는지 별도 측정하며 실제 답변/라우팅 기능을 구현했다고 주장하지 않는다.

## 검증·산출물

- 설계, 리서치 근거, 300문항 전체 Markdown/JSON, split, 출처/gold, 라운드별 설정·각 질문의 모든 반환 원문·점수·순위·판정·처리시간, 요약표, 선택 근거, 최종100문항 비교, 실패 사례 전체, 별도 FINAL-REVIEW.md, 파일 해시 목록.
- 결과는 검색 평가다. LLM 답변 생성·고객 문의 실제 처리·운영 승인·Customer 업로드는 범위 밖이다.
- 모든 실험 행 수 및 질문 ID 대조, source SHA 불변, 중복/누락 없음, split 그룹 분리, 결과와 Markdown 대응, 회귀 테스트·Ruff로 최종검수한다.
- 실패를 제외하거나 샘플 질문만 보고서에 싣지 않는다. 최종검수는 완료된 절차와 검색 품질의 잔여 문제를 별도로 판정한다.

## 로컬 적용 상세 (코드 적용 전)

선정된 검색 엔진을 새 `scripts/query_policy_knowledge.py` 명령에서 재사용한다. 기본은 개발용 결과로 고정한 방식이며 `--baseline`으로 R1을 실행한다. 평가에 사용한 엔진 파일은 해시로 잠그고 변경하지 않는다. 정책·질문 정답은 실행 입력에 넣지 않고, 원문 청크와 본문/제목 임베딩만 사용한다. 기존 로컬 Chroma는 읽기 조회하고 새 데이터 업로드는 하지 않는다. 결과는 원문 근거 후보이며 답변 생성이나 개인 상태 조회로 표시하지 않는다. 최종평가의 구절 회수율 개선과 정책 회수율 손실을 함께 공개하므로 운영 기본 검색기는 이번에 교체하지 않는다. 버전 경계, 확장 예산, 후보 없는 검색, 순위 결합을 회귀 검증한다.
