## 1. 서비스 소개

챱챱은 고객이 플랜과 구독 설정을 선택하고 도시락을 정기적으로 배송받는 서비스다.

## 2. 핵심 용어

| 공식 용어 | 쉬운 뜻 | 사용하지 않는 표현 |
|---|---|---|
| 구독 | 고객별로 하나만 유지하면서 신청·이용·해지·종료·재신청 상태를 관리하는 지속적인 이용 관계 | |
| 진행 중 구독 | 상태가 `확정 대기`, `시작 예정`, `이용 중`, `해지 예정` 중 하나인 구독 | |
| 구독 해지 | 자동 갱신을 중단하고 이미 시작된 이용 기간의 마지막 날에 구독을 끝내는 것 | |
| 회원 탈퇴 | 인증 서비스가 계정·세션·개인정보를 처리하는 일. 구독 해지나 환불을 대신 실행하지 않음 | 계정 해지 |
| 이용 기간 | 고객이 구독 서비스를 이용하는 연속된 28일 | |
| 첫 이용 기간 시작일 | 첫 결제 후 가능한 가장 빠른 실제 배송일로서, 첫 28일 이용 기간이 시작되는 날짜 | 첫 구독 시작일 |
| 플랜 | 도시락 1개당 가격과 제공 범위를 정하는 구독 종류 | |

| 반영 기준일 | 처리 기준 시각을 기준으로 배송이나 변경된 설정을 가장 빠르게 반영할 수 있는 날짜 | 실제 배송일 |
| 주문 | 실제 배송일 하나에 대응하여 생성되는 한 건 | |
| 배송 | 하나의 배송일에 정해진 배송지와 배송 시간대로 도시락을 한 번 전달하는 것 | |
| 배송일 | 구독 설정과 반영 기준일을 적용한 뒤 실제로 배송하기로 정해진 날짜 | |
| 배송 요일 | 고객이 28일 이용 기간 동안 매주 반복해서 배송받기로 선택한 요일 | |
| 배송 시간대 | 고객이 도시락을 받기로 선택하는 시간 구간 | |
| 배송지 | 고객이 도시락을 받도록 지정한 장소 | |
| 배달 방식 | 배송지마다 선택하는 필수 배달 요청사항 | 배송 요청사항 |
| 비대면 보관 약관 | 고객 부재 시 문 앞 또는 지정 장소에 보관될 수 있음을 고객에게 알리고 동의받는 필수 약관 | |
| 고객 약관 동의 | 고객이 특정 버전의 약관에 동의한 변경 불가 기록 | 약관 동의 상태 |

| 자동결제수단 | 첫 구독 결제·정기결제·구독 설정 변경 추가 결제에 사용할 수 있도록 등록하고 검증한 결제수단 | 일반결제 카드 |
| 현재 결제수단 | 등록된 자동결제수단 중 다음 결제에 우선 사용하는 하나의 결제수단 | 기본 카드 |
| 추가 결제 | 구독 설정 변경으로 남은 이용금액이 늘어났을 때 고객 확인 후 차액을 결제하는 것 | 정기결제 |
| 원 결제 취소 결제 거래 | 별도 엔터티가 아닌 `결제 거래` 중 기존 성공 원 결제의 전액 또는 일부를 취소하는 거래. 환불 업무에 연결되며 실제 취소 결과를 기록함 | 취소 거래 |
| 부분 취소 | 원 결제금액 중 일부를 취소하여 환불하는 것 | 마이너스 결제 |
| 전액 취소 | 원 결제의 취소 가능 잔액 전체를 취소하여 환불하는 것 | 마이너스 결제 |
| 배송 건 환불 | 배달·배송 서비스가 환불 대상으로 확정한 배송 건과 연결된 주문 한 건의 실제 결제금액을 환불하는 것 | 고객 개별 주문 취소 |
| 확인 필요 환불 | 여러 원 결제 취소 중 일부는 성공하고 다음 취소가 실패하여, 성공·실패 내역과 남은 금액을 보존하고 현재 프로젝트에서 추가 처리하지 않는 환불 | 처리 중 환불 |

## 4. 현재 정책

### POL-COMMON-001 — 날짜와 시간 기준

- 마지막 확정일: 2026-08-12
- 적용 대상: 구독·결제·주문에 사용하는 모든 날짜와 시각
- 정책 내용: 구독·결제·주문에 사용하는 날짜와 시각은 대한민국 표준시인 KST를 기준으로 계산한다.

### POL-TERMS-001 — 비대면 보관 약관 동의

- 마지막 확정일: 2026-09-01
- 적용 대상: 첫 구독 신청을 완료하려는 고객과 그 뒤 생성되는 주문
- 정책 내용: 고객은 첫 구독 신청을 완료하고 첫 결제를 요청하기 전에 현재 적용 중인 필수 비대면 보관 약관에 동의해야 한다. 동의하지 않으면 구독·이용 기간·설정·주문·결제 거래를 생성하거나 결제를 요청하지 않는다.
- 약관은 약관 종류와 버전별 문서로, 고객 약관 동의는 고객·약관·동의 시각을 가진 변경 불가 기록으로 각각 보존한다. 고객이 같은 약관 버전에 다시 동의 요청을 보내도 기존 동의 기록을 재사용하며, 과거 동의 기록을 수정·삭제하지 않는다.
- 고객이 동의를 요청할 때는 화면에서 확인한 약관 버전과 서버의 현재 적용 필수 약관 버전이 일치해야 한다. 버전이 다르면 동의를 확정하지 않고 현재 약관을 다시 확인해야 한다.
- 주문은 생성 당시 적용된 고객 약관 동의 기록 하나를 참조한다.
- 현재 MVP에서는 필수 비대면 보관 약관의 적용 버전을 변경하지 않는다. 새 약관 버전 등록, 기존 고객 재동의 안내, 재동의하지 않은 고객의 정기결제·주문 처리 방식은 후속 범위다. 다만 약관과 고객 동의 기록에는 버전을 보존한다.

#### MVP 초기 적용 약관

| 항목 | 확정값 |
|---|---|
| 버전 | `1` |
| 제목 | `비대면 보관 약관` |
| 필수 여부 | 필수 |
| 현재 적용 여부 | 현재 적용 |

약관 본문:

> 챱챱은 고객이 지정한 배송지와 배달 요청사항에 따라 구독 상품을 배송합니다.
>
> 1. 고객이 배송 시 상품을 직접 수령하지 못하는 경우, 고객이 배송지에 설정한 배달 방식과 요청사항에 따라 상품이 문 앞 또는 고객이 지정한 장소에 보관될 수 있습니다.
>
> 2. 고객은 배송지마다 다음 배달 방식 중 하나를 선택합니다.
>    - 직접 받을게요
>    - 문 앞 배송
>    - 기타
>
>    `기타`를 선택한 경우 고객이 입력한 요청사항을 해당 배송지의 배달 요청사항으로 사용합니다.
>
> 3. 구독 주문은 주문이 생성될 당시 확정된 배송지와 배달 요청사항을 기준으로 처리됩니다.
>
> 4. 본 약관은 첫 구독 신청을 완료하고 첫 결제를 진행하기 전에 반드시 동의해야 하는 필수 약관입니다. 본 약관에 동의하지 않은 경우 첫 구독 신청 및 결제를 진행할 수 없습니다.
>
> 5. 고객의 동의 사실은 동의한 약관의 버전 및 동의 시각과 함께 기록됩니다. 동일한 약관 버전에 다시 동의하더라도 기존 동의 기록이 유지됩니다.
>
> 6. 구독을 통해 생성되는 주문은 해당 고객이 동의한 비대면 보관 약관 기록을 기준으로 생성됩니다.
>
> 본인은 위 내용을 확인하였으며, 배송 과정에서 직접 수령하지 못하는 경우 선택한 배달 방식 및 요청사항에 따라 상품이 문 앞 또는 지정한 장소에 보관될 수 있음에 동의합니다.

현재 정책에서 별도로 확정하지 않은 배송 후 분실·도난·변질, 책임 이전, 손해배상 제한 등의 면책 문구는 MVP 약관 v1에 임의로 추가하지 않는다.

예시:

- 고객이 비대면 보관 약관 v1에 동의한 뒤 첫 구독을 신청하면, 이후 그 구독에서 생성되는 주문은 v1 동의 기록을 참조한다.
- 고객이 화면에서 확인한 버전과 현재 적용 버전이 다르면 해당 요청으로 동의를 확정하지 않고 현재 약관을 다시 확인한다.
- 현재 MVP에서 v2를 새로 적용하는 기능은 제공하지 않는다. 따라서 v2 미동의 상태에서 정기결제·주문을 어떻게 처리할지는 현재 구현 대상이 아니다.

### POL-ADDRESS-001 — 배송지별 배달 요청사항

- 마지막 확정일: 2026-08-24
- 적용 대상: 고객이 등록·수정하는 모든 배송지
- 정책 내용: 고객은 배송지마다 배달 방식 하나를 필수로 선택하고 공동현관 비밀번호는 필요한 경우에만 문자열로 입력한다. 기본 주소와 우편번호는 필수이며, 상세 주소는 선택 입력이다. **현재 MVP에서는 기본 주소 문자열에 `대구`가 포함된 경우에만 배송 가능으로 판단**한다. `대구`가 포함되지 않으면 배송지를 등록·수정할 수 없다. 주문을 생성할 때 해당 배송지의 배달 요청사항을 주문 데이터에 복사한다. 대구 단일 지역 MVP에서는 별도 지역 코드를 사용하지 않으며, 행정구역·좌표·우편번호를 이용한 정확한 지역 판정은 현재 범위에 포함하지 않는다.

#### 배달 방식

| 문자열 코드 | 고객에게 표시하는 문자열 |
|---|---|
| `DIRECT` | 직접 받을게요 |
| `DOORSTEP` | 문 앞 배송 |
| `OTHER` | 기타 |

- 배달 방식은 나중에 항목을 추가할 수 있도록 별도 코드 목록으로 관리한다.
- `OTHER(기타)`를 선택한 경우에만 고객이 직접 입력한 문자열을 필수로 받는다.
- `DIRECT` 또는 `DOORSTEP`을 선택한 경우에는 고객 직접 입력 문자열을 받거나 저장하지 않는다.
- 주문 데이터에는 고객이 선택한 배달 방식 문자열 코드를 담고, `OTHER`인 경우에만 고객 직접 입력 문자열도 함께 담는다.
- 고객이 요청한 배달 방식과 배달 기사가 실제로 수행한 배달 방식은 서로 다른 정보로 구분한다.

#### 예시

- `DIRECT`를 선택한 배송지로 주문을 생성하면 주문에는 `DIRECT`가 유지되고 고객 직접 입력 문자열은 없다.
- `OTHER`를 선택하고 `경비실에 맡겨주세요`라고 입력하면 주문에는 `OTHER`와 고객 직접 입력 문자열 `경비실에 맡겨주세요`가 함께 유지된다.

### POL-SUBSCRIPTION-005 — 구독 이용 기간

- 마지막 확정일: 2026-09-06
- 적용 대상: 모든 구독
- 정책 내용: 하나의 이용 기간은 시작일을 포함하여 연속된 28일이며, 시작일을 1일째로 계산하고 28일째 되는 날에 끝난다.

#### 핵심 제약

- 일요일과 공휴일도 이용 기간의 날짜 수에는 포함한다.
- 일요일과 공휴일에는 주문과 배송이 없더라도 이용 기간의 종료일을 뒤로 미루지 않는다.
- 시작일 `00:00 KST`가 도달한 `시작 예정` 이용 기간은 `진행 중`이 되고, 정상적으로 마지막 날이 지난 `진행 중` 이용 기간은 `종료`가 된다.
- 자동 갱신에서는 이전 기간의 `진행 중 → 종료`와 다음 기간의 `시작 예정 → 진행 중` 전환을 같은 로컬 트랜잭션에서 처리한다.

#### 예시

8월 10일에 이용 기간이 시작하면 8월 10일을 1일째로 계산하여 9월 6일에 끝난다.

### POL-SUBSCRIPTION-006 — 배송 요일별 인원수 설정

- 마지막 확정일: 2026-08-15
- 적용 대상: 모든 구독
- 정책 내용: 고객은 선택한 각 배송 요일의 인원수를 1명부터 6명까지 서로 다르게 설정할 수 있다.

#### 예시

월요일은 1명, 수요일은 2명, 금요일은 6명으로 설정할 수 있다.

### POL-SUBSCRIPTION-007 — 첫 이용 기간 시작일

- 마지막 확정일: 2026-08-25
- 적용 대상: 첫 구독을 신청하는 고객
- 정책 내용: 첫 이용 기간 시작일은 구독 신청의 처리 기준 시각으로 계산한 반영 기준일 이후 가능한 가장 빠른 실제 배송일로 정하고, 첫 결제 성공 시 시작 예정 상태로 확정한다.

#### 핵심 제약

- 유효한 구독 신청을 접수할 때 처리 기준 시각을 확정하고 `POL-SUBSCRIPTION-013`을 적용하여 반영 기준일을 계산한다.
- 반영 기준일부터 고객이 선택한 배송 요일을 확인하고, 일요일과 공휴일을 제외한 가장 빠른 실제 배송일을 찾는다.
- 결제 요청 전에 구독·첫 이용 기간·설정·주문을 실제 데이터로 생성하고 `확정 대기` 상태로 둔다.
- 첫 결제 성공 응답을 받으면 결제 데이터를 기록한 뒤 구독 상태를 `확정 대기`에서 `시작 예정`으로 바꾸고, 미리 생성한 첫 이용 기간·설정·주문을 유효하게 확정한다.
- PG가 결제 거절을 명확히 응답하거나 Provider 인증·권한·연동 설정 오류를 명시적으로 응답하면 결제 처리 시도와 실패 결제 거래를 기록하고, 미리 생성한 구독·첫 이용 기간·첫 설정·주문을 모두 `결제 실패`로 확정한다. 결제 실패 주문은 배송과 주문 전달에 사용하지 않는다.
- timeout·연결 실패·응답 불명확·Provider 5xx·429·`AlreadyPaidError`·응답 파싱 실패·알 수 없는 상태로 실제 승인 여부를 확정할 수 없으면, 같은 첫 구독 요청 안에서 같은 외부 `paymentId`의 결제 단건 조회를 한 번만 수행한다. 이 조회가 `PAID` 또는 `FAILED`를 명확히 반환하면 그 결과로 성공 또는 실패를 확정한다. 조회가 실패하거나 그 밖의 상태를 반환하면 결제 거래는 `처리 중`, 구독·첫 이용 기간·첫 설정·주문은 `확정 대기`로 유지한다. 새 사전 데이터·새 PG 결제 요청·추가 단건 조회·자동 복구는 현재 MVP에서 제공하지 않는다.
- 가능한 가장 빠른 실제 배송일의 `00:00 KST`에 구독 상태를 `시작 예정`에서 `이용 중`으로 바꾸고 첫 28일 이용 기간을 시작한다.
- 실제 배송의 성공·실패·완료 여부는 `이용 중` 상태로 바꾸는 조건에 영향을 주지 않는다.
- 반영 기준일이 고객이 선택하지 않은 요일이거나 공휴일이면 첫 이용 기간 시작일은 그보다 늦어질 수 있다.

#### 예시

### POL-SUBSCRIPTION-013 — 처리 기준 시각에 따른 반영 기준일

- 마지막 확정일: 2026-08-25
- 적용 대상: 첫 구독 신청, 재신청 또는 구독 설정 변경 요청
- 정책 내용: 유효한 고객 요청을 접수할 때 `처리 기준 시각`을 한 번 확정하고, 이 시각을 기준으로 반영 기준일 또는 변경 적용일을 계산한다. 결제·환불 완료 시각으로 다시 계산하지 않는다. 정기결제는 이 규칙의 적용 대상이 아니다.

#### 기본 규칙

- 처리 기준 시각이 `14:00:00 KST`보다 전이면 다음 날을 반영 기준일로 한다.
- 처리 기준 시각이 `14:00:00 KST`부터면 다다음 날을 반영 기준일로 한다.
- 반영 기준일이 일요일이면 월요일로 조정한다.

#### 핵심 제약

- 첫 결제와 재신청에서는 이 규칙으로 반영 기준일을 계산한 뒤, `POL-SUBSCRIPTION-007`에 따라 그 날 이후 고객이 선택한 배송 요일 중 일요일·공휴일이 아닌 가장 빠른 실제 배송일을 첫 이용 기간 시작일로 정한다.
- 구독 설정 변경에서는 이 규칙으로 변경 적용일을 계산한다.
- 계산 결과로 구독·이용 기간·설정·주문과 결제금액을 먼저 생성한 뒤 PG 결제 또는 환불을 요청하며, 성공 전까지 관련 데이터를 대기 상태로 둔다.
- 외부 결제 처리 중 14:00 경계를 지나더라도 해당 처리 건의 기준 시각과 주문·결제금액을 바꾸지 않는다.
- 반영 기준일이 공휴일이거나 고객이 선택한 배송 요일이 아니면, 실제 배송일은 그 이후 고객이 선택한 배송 요일 중 일요일·공휴일이 아닌 가장 빠른 날짜가 된다.
- 정기결제 성공 후 다음 이용 기간 주문을 생성할 때에는 이 규칙을 적용하지 않고 `POL-SUBSCRIPTION-001`을 적용한다.

#### 예시

| 화요일 13:00 | 수요일 |

### POL-SUBSCRIPTION-014 — 고객당 하나의 구독 관계

- 마지막 확정일: 2026-08-20
- 적용 대상: 새 구독을 신청하는 모든 고객
- 정책 내용: 인증 서비스가 제공한 같은 고객 식별자를 기준으로 구독 관계는 고객당 하나만 유지한다. 첫 결제 실패·시작 취소·종료 후 다시 구독하더라도 기존 구독을 재사용하고, 현재 상태와 구독 상태 이력으로 전체 생명주기를 관리한다.

#### 핵심 제약

- `확정 대기`, `시작 예정`, `이용 중`, `해지 예정` 상태는 모두 진행 중 구독에 포함한다.
- 해지 예정 구독은 현재 이용 기간 마지막 날까지 진행 중 구독으로 유지하므로 종료되기 전에는 새 구독을 시작할 수 없다.
- 09:00 정기결제 실패 후 13:00 재시도를 기다리는 동안에도 기존 구독 상태를 유지하므로 새 구독을 시작할 수 없다.
- 첫 결제 실패가 명확히 확정되면 기존 구독은 `결제 실패`로 확정한다. 고객이 다시 신청하면 같은 구독을 `확정 대기`로 바꾸고 새 계산 결과로 다음 순번 데이터를 생성한다. 결제 결과가 불명확한 `처리 중` 거래가 있으면 재신청하지 않는다.
- `시작 취소` 또는 `종료` 후 재신청할 때에도 같은 구독을 `확정 대기`로 바꾸며, 각 변경 전·후 상태와 사유·시각은 구독 상태 이력에 남긴다.
- 재신청에서는 실패·취소·종료된 이용 기간·설정·주문을 되돌리지 않고 새 이용 기간·설정·주문을 생성한다.
- 이용 기간 순번과 설정 버전 순번은 재신청하더라도 초기화하지 않고 계속 증가한다.
- 같은 고객의 구독 신청이 동시에 여러 건 처리되더라도 구독은 하나만 생성되어야 한다.

#### 예시

- `이용 중` 구독이 있는 고객이 새 구독을 신청하면 새 첫 결제를 진행하지 않고 기존 구독을 유지한다.
- 구독이 `해지 예정`이면 현재 이용 기간이 끝나 `종료` 상태가 될 때까지 새 구독을 시작할 수 없다.
- 구독이 `종료` 상태인 고객이 다시 신청하면 기존 구독을 `확정 대기`로 바꾸고 다음 순번의 이용 기간과 설정 버전을 생성한다.

### POL-ORDER-001 — 이용 기간의 주문 생성

- 마지막 확정일: 2026-08-18
- 적용 대상: 첫 구독 신청 또는 정기결제를 처리하는 고객
- 정책 내용: 처리 기준 시각으로 이용 기간·배송일·금액을 계산하고, 결제를 요청하기 전에 해당 이용 기간의 실제 배송일마다 주문을 한 건씩 실제 데이터로 생성한다.

#### 핵심 제약

- 첫 이용 기간에는 첫 이용 기간 시작일인 실제 첫 배송일부터 이용 기간 종료일까지 배송 요일을 적용하여 주문을 생성한다.
- 첫 이용 기간의 주문은 첫 결제 전에 `확정 대기`로 생성하고, PG 성공 응답 후 `유효`로 확정한다.
- 첫 주문은 구독이 `이용 중`으로 바뀌기 전날 `15:00 KST`에 전달될 수 있다.
- 첫 주문이 전달 완료되기 전에는 고객의 시작 취소 대상이 될 수 있으며, 시작 취소가 확정된 주문은 전달하지 않는다.
- 다음 이용 기간 주문도 정기결제 전에 `확정 대기`로 생성하고, PG 성공 응답 후 `유효`로 확정한다.
- 확정 대기 주문은 고객의 유효 주문 조회와 주문 전달 대상에서 제외한다.
- 첫 결제 실패 주문은 즉시 `결제 실패`로 확정한다. 정기결제 최종 실패 주문도 `결제 실패`이며, 이 경우에는 현재 이용 기간의 바로 다음 기간 주문만 해당한다. 첫 구독 취소 또는 정기결제 재시도 중 해지로 시작 취소가 확정된 주문은 `시작 취소`로 남긴다.
- 각 이용 기간의 최초 주문 묶음은 한 번 생성한다. 첫 결제 실패 뒤 재신청에는 다음 순번의 새 이용 기간과 새 주문 묶음을 생성한다. 이용 중 설정 변경에는 변경 대상 배송일의 대체 주문이 추가될 수 있다.
- 일요일과 공휴일에는 주문을 생성하지 않는다.
- 주문 수는 고정된 12건이 아니라 실제 배송일 수에 따라 달라진다.

#### 예시

배송 요일이 월요일·수요일·금요일인 고객의 신청을 8월 10일 월요일 15:00에 접수하면 반영 기준일은 8월 12일 수요일이다. 해당 날짜가 선택 요일이므로 첫 이용 기간도 8월 12일에 시작하도록 계산하고, 결제 전에 8월 12일부터 28일 동안의 실제 배송일마다 주문을 `확정 대기`로 생성한다.

### POL-ORDER-005 — 주문별 도시락 수량

- 마지막 확정일: 2026-08-15
- 적용 대상: 실제 배송일마다 생성되는 주문
- 정책 내용: 주문 한 건의 도시락 수량은 해당 배송일의 요일에 설정된 인원수와 같다.

#### 예시

수요일 인원수를 3명으로 설정했다면 수요일에 생성되는 주문 한 건에는 도시락 3개가 포함된다. 월요일 인원수가 1명이면 월요일 주문에는 도시락 1개가 포함된다.

### POL-ORDER-006 — 일요일·공휴일 주문 생성 제외

- 마지막 확정일: 2026-08-13
- 적용 대상: 모든 구독의 주문 생성
- 정책 내용: 일요일과 대한민국의 공식 공휴일·대체공휴일에는 주문을 생성하지 않는다. 해당 날짜의 주문을 다른 날짜로 옮기지 않는다.

#### 핵심 제약

- 일요일은 배송 요일로 선택할 수 없다.
- 반영 기준일이나 변경 적용일이 공휴일이어도 그 날짜에는 주문과 배송이 없다.
- 공휴일 때문에 주문이 제외되어도 고객이 선택한 배송 요일 설정은 바뀌지 않는다.

#### 예시

고객이 월요일·수요일·금요일을 선택했고 수요일이 공휴일이면 그 주에는 월요일과 금요일 주문만 생성한다. 수요일 주문을 목요일 등에 대신 생성하지 않는다.
