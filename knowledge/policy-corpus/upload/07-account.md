### AUTH-POL-ACC-003 소셜 계정 연결

- 지원 Provider는 `KAKAO`, `GOOGLE`이다.
- `(provider, providerUserId)`는 전체 계정에서 유일하다.
- 한 사용자는 Provider 종류별로 최대 한 계정만 연결한다.
- 같은 `identityKey`를 확인한 경우에만 기존 사용자에게 새 Provider를 연결한다.
- 이메일·전화번호·이름이 같다는 이유로 계정을 자동 통합하지 않는다.
- 이미 다른 사용자에게 연결된 Provider 계정을 자동 이전하지 않는다.

### AUTH-POL-SIGN-001 로그인 방식

| 계정 유형 | 로그인 방식 |
|---|---|
| `CUSTOMER`, `RIDER` | 카카오·구글 소셜 로그인 |
| `ADMIN`, `SUPER_ADMIN` | 관리자 아이디·비밀번호 |

일반 사용자 이메일·비밀번호 로그인과 관리자 소셜 로그인은 제공하지 않는다.

### AUTH-POL-SIGN-005 만 14세 미만 처리

- 가입 시 PortOne/KCP 재조회 결과의 생년정보로 만 14세 이상인지 서버에서 확인한다.
- 만 14세 미만이면 가입을 완료하지 않는다.

### AUTH-POL-SES-001 만료 기준

| 구분 | Access Token | Refresh 유휴 만료 | 세션 절대 만료 | 유휴 연장 |
|---|---:|---:|---:|:---:|
| 일반 사용자 | 30분 | 마지막 정상 사용 후 14일 | 최초 로그인 후 30일 | 적용 |

- 유휴 만료가 남아 있어도 절대 만료를 넘을 수 없다.

### AUTH-POL-SES-003 세션 폐기 범위

| 행위 | 폐기 범위 |
|---|---|
| 로그아웃 | 현재 기기·브라우저 세션 |
| 회원 탈퇴 | 사용자의 모든 세션 |
| `CUSTOMER ↔ RIDER` 변경 | 대상 사용자의 모든 세션 |

| Refresh Token 재사용 탐지 | 해당 Token 계열 세션 |

기존 Access Token은 자체 만료까지 남을 수 있다. 이번 프로젝트에서는 Gateway `authVersion` 비교를 구현하지 않는다.

### AUTH-POL-CNS-003 가입 동의

- 현재 이용약관과 가입에 필요한 개인정보 처리 항목을 완료해야 가입할 수 있다.
- 이메일 마케팅은 선택이며 거절해도 가입·로그인·핵심 서비스 이용을 제한하지 않는다.
- 미선택 마케팅 정책은 `DECLINED`로 저장한다.
- 필수 정책은 일반 마케팅 동의 변경 API에서 철회할 수 없다. 개인정보 처리 정지·삭제 요구는 별도의 정보주체 권리 절차로 처리한다.

### AUTH-POL-CNS-004 이메일 광고

- 광고성 이메일은 명확한 `MARKETING_EMAIL = AGREED`가 있을 때만 대상으로 선정한다.
- 활성 사용자, 이메일 존재와 현재 활성 마케팅 Version 동의를 모두 확인한다.
- 새 마케팅 Version은 과거 동의를 자동 승계하지 않는다.
- 사용자는 마이페이지에서 동의·철회를 쉽게 수행할 수 있어야 하며 철회를 이유로 로그인 절차를 불필요하게 복잡하게 만들지 않는다.

### AUTH-POL-WD-006 재가입

- 탈퇴 후 `identityKey`와 소셜 연결을 제거하므로 같은 사람이 다시 가입하면 새로운 `userId`를 발급한다.
- 탈퇴 전 역할, 마케팅 동의, 대표 주소와 세션을 자동 복구하지 않는다.

### AUTH-POL-IMG-001 저장·검증

- 대상은 `CUSTOMER`, `RIDER`이며 사용자당 한 장이다.
- 허용 형식은 JPEG, PNG, WebP이고 SVG는 금지한다.
- 최대 크기는 5MB다.
- 확장자와 Content-Type만 믿지 않고 실제 파일 형식을 서버에서 확인한다.

### AUTH-POL-PRI-008 권리행사

이용자는 법령이 정한 범위에서 자신의 개인정보에 대해 다음을 요구할 수 있다.

- 처리 여부 확인과 열람
- 정정·삭제
- 처리정지
- 동의 철회
- 회원 탈퇴

서비스는 본인 또는 정당한 대리인인지 확인한 뒤 법령상 제한·거절 사유가 없으면 처리한다. 거절·제한 시 사유와 이의제기 방법을 알린다.

### AUTH-POL-PRI-009 서비스별 요청 라우팅

| 요청 정보 | 담당 서비스 |
|---|---|
| 계정, 소셜 연결, 역할, 인증 세션, 마케팅 동의 | Auth-Service |
| 주소록·주소 상세 | Subscription-Service |
| 주문·결제·구독 | 각 소유 서비스 |
| 배송 업무 | Delivery-Service |

Auth-Service가 다른 서비스 DB를 직접 수정하지 않는다. 통합 권리행사 창구가 요청을 받은 경우 소유 서비스에 안전하게 전달하고 처리 결과를 추적한다.
