### POL-SUBSCRIPTION-001 — 구독 자동 갱신

- 마지막 확정일: 2026-09-06
- 적용 대상: 구독을 이용 중인 고객
- 정책 내용: 고객이 구독을 해지하지 않고 정기결제에 성공하면, 현재 28일 이용 기간이 끝난 다음 날부터 새로운 28일 이용 기간이 이어진다.

#### 핵심 제약

- 이용 기간 사이에는 빈 날짜나 겹치는 날짜가 없다.
- 다음 이용 기간에는 그때까지 마지막으로 유효하게 확정된 구독 설정을 적용한다. 이전 이용 기간의 주문 데이터를 복사하지 않고, 해당 설정과 요일별 배송 조건으로 새 주문을 생성한다.
- 정기결제 재시도까지 실패하면 다음 이용 기간을 시작하지 않는다.
- 다음 이용 기간 28일 안에서 고객이 선택한 배송 요일이면서 일요일·공휴일이 아닌 날짜마다 주문을 생성한다. 이용 기간 첫날이 실제 배송일이면 그 날 주문도 생성할 수 있다.
- 정기결제에서는 `POL-SUBSCRIPTION-013`의 반영 기준일 또는 변경 적용일 계산을 다시 적용하지 않는다.
- 다음 이용 기간과 주문은 결제 전에 `확정 대기` 상태로 생성하고, 정기결제 성공 응답 후에만 유효하게 확정한다.
- 정기결제 성공으로 `시작 예정`이 된 다음 이용 기간의 시작일 `00:00 KST` 이후에는 이전 `진행 중` 이용 기간을 `종료`, 다음 이용 기간을 `진행 중`으로 같은 처리에서 전환한다.
- 정상 자동 갱신에서는 구독 전체가 계속 `이용 중`이므로 구독 상태 이력을 추가하거나 Auth·Customer에 구독 상태 변경 Event를 발행하지 않는다.

#### 예시

현재 이용 기간이 8월 10일부터 9월 6일까지이고 9월 6일 정기결제에 성공하면, 다음 이용 기간은 9월 7일부터 10월 4일까지 이어진다.

### POL-SUBSCRIPTION-002 — 구독 설정 변경

- 마지막 확정일: 2026-09-06
- 적용 대상: 구독을 이용 중인 고객
- 정책 내용: 고객은 현재 이용 기간에도 플랜·배송 요일·배송 요일별 인원수·배송지·배송 시간대를 변경할 수 있다. 확정된 변경은 변경 적용일부터 반영하며, 고객이 다시 변경하기 전까지 이후 이용 기간에도 계속 적용한다.

#### 적용 시점

- 변경 적용일은 유효한 변경 요청을 접수할 때 확정한 처리 기준 시각에 `POL-SUBSCRIPTION-013`을 적용하여 계산한다.
- 변경 적용일보다 앞선 배송에는 기존 구독 설정을 유지한다.
- 변경 적용일부터는 변경된 구독 설정을 적용한다. 실제 첫 배송일은 고객이 선택한 배송 요일과 일요일·공휴일 제외 규칙에 따라 변경 적용일보다 늦을 수 있다.
- 같은 변경 적용일의 설정 변경이 연속으로 확정되면 가장 마지막에 확정된 설정만 해당 날짜부터 적용한다. 먼저 확정됐지만 실제 적용되기 전에 대체된 설정 버전은 삭제하거나 실패로 바꾸지 않고, 적용 시작일과 적용 제외 시작일이 같은 빈 적용 구간의 확정 이력으로 보존한다.
- 정상 흐름의 설정 변경 성공·실패와 실제 일부 취소 성공 시의 `확인 필요` 결과는 고객의 변경 요청을 처리하는 동안 결정한다. 일부 취소 성공이면 새 주문은 `변경 대기`로 남지만 기존 주문이 계속 `유효`하므로 15:00에는 기존 주문을 발행한다.

#### 이용금액 처리

- 이미 결제된 이용 기간에서는 변경 적용일 이후에 남은 주문만 새 조건으로 다시 계산한다. 변경 적용일보다 앞선 주문은 다시 계산하지 않는다.
- 변경 대상 기존 주문의 이용금액은 연결된 결제금액 배분의 남은 취소 가능 금액 합계로, 새 이용금액은 새 설정으로 만든 주문의 실제 배분금액 합계로 계산한다. 배송일별 금액을 서로 직접 대응시키지 않고 두 주문 묶음의 총액 차이만 추가 결제 또는 환불한다.
- 새 이용금액이 이미 결제한 금액보다 많으면 변경 내용·차액·현재 결제수단을 고객에게 확인받은 뒤, 고객이 변경과 결제를 함께 요청한 경우에만 현재 결제수단으로 차액을 추가 결제한다.
- 새 이용금액이 이미 결제한 금액보다 적으면 변경을 저장할 때 줄어든 금액을 해당 주문에 배분된 하나 이상의 원 결제에서 부분 취소한다.
- 금액이 줄어든 하나의 새 구독 설정 버전에는 감액 환불을 최대 한 건만 생성한다. 여러 원 결제를 취소해야 하면 하나의 환불에 원 결제별 원 결제 취소 결제 거래를 여러 건 연결한다.
- 배송 요일별 배송지나 배송 시간대만 변경하면 이용금액을 다시 계산하지 않는다.
- 차액 없음, 추가 결제 성공 또는 필요한 모든 원 결제 취소 성공으로 변경을 확정할 때에는 기존 주문을 비활성 이력으로 보존하고, 기존 원 결제의 남은 결제금액과 설정 변경 추가 결제금액을 새 주문별 실제 배분금액에 맞게 재배분한다. 주문 상태 전환과 배분 재구성은 하나의 로컬 트랜잭션에서 처리한다.
- 설정 변경이 실패하거나 감액 취소가 일부만 성공하여 변경을 확정하지 못하면 결제금액 배분을 새 주문으로 재구성하지 않는다.

#### 조건을 충족하지 못하면

- 변경 요청을 접수하면 새 구독 설정 버전과 적용일 이후의 새 주문을 실제 데이터로 먼저 생성하되, 결제·환불 결과가 확정될 때까지 `변경 대기` 상태로 둔다.
- 추가 결제에 실패하면 미리 생성한 새 설정과 주문을 `변경 미적용` 상태로 바꾸고 기존 구독 설정과 주문을 유지한다.
- 여러 원 결제의 취소를 시작하기 전에 실패하면 미리 생성한 새 설정과 주문을 `변경 미적용` 상태로 바꾸고 기존 구독 설정과 주문을 유지하며, 고객에게 변경되지 않았음을 알린다. 첫 원 결제 취소부터 실패하면 같은 처리와 함께 해당 환불을 `실패`로 기록한다.
- 감액 환불이 첫 취소부터 실패한 뒤 고객이 다시 설정을 변경하면, `변경 미적용`인 과거 설정 버전과 환불을 다시 사용하지 않는다. 새 변경 요청으로 다음 설정 버전과 새 환불 업무를 만든다.
- 정상 흐름에서는 필요한 여러 원 결제 취소가 모두 성공한다고 가정하여 구현한다.
- 실제로 일부 원 결제 취소만 성공하면 새 설정과 주문을 `변경 대기`, 기존 설정과 주문을 `유효`로 유지하고 기존 환불 상태를 `확인 필요`로 둔다. 새 환불은 생성하지 않으며, 성공·실패 내역과 미처리 금액은 보존하지만 현재 프로젝트에서는 이후 추가 처리와 완료 기능을 제공하지 않고 변경 완료로 확정하지 않는다.

#### 예시

- 화요일 13:00에 변경 요청을 접수하면 수요일부터 변경된 설정을 반영할 수 있다.
- 화요일 15:00에 변경 요청을 접수하면 목요일부터 변경된 설정을 반영할 수 있다.
- 화요일 15:00에 수요일 주문이 전달 완료된 뒤 설정을 변경하면 수요일 주문은 유지하고 목요일 이후 주문부터 새 설정을 적용한다.
- 토요일 15:00에 변경 요청을 접수하면 바로 다음 월요일부터 변경된 설정을 반영할 수 있다. 단, 월요일이 공휴일이거나 고객이 월요일을 선택하지 않았다면 실제 첫 배송일은 그 뒤의 선택된 실제 배송일이다.
- 변경 적용일부터 남은 이용금액이 20,000원 늘어나면 변경을 저장할 때 20,000원을 추가 결제한다. 결제에 실패하면 변경 전 설정을 유지한다.
- 변경 적용일 이후 11,900원인 월요일 주문을 없애고 11,900원인 화요일 주문을 새로 만들면 총액 차이는 0원이다. 외부 결제·환불 없이 월요일 주문을 비활성 이력으로 남기고 기존 결제금액의 현재 사용처를 화요일 새 주문으로 재배분한다.

### POL-SUBSCRIPTION-003 — 구독 해지

- 마지막 확정일: 2026-09-06
- 적용 대상: `시작 예정` 또는 `이용 중`인 구독의 고객
- 정책 내용: 고객이 이용 중인 구독을 해지하면 자동 갱신을 중단한다. 이미 결제되어 이용 중인 현재 이용 기간은 즉시 종료하거나 환불하지 않고 마지막 날까지 유지한다. 결제 성공한 시작 예정 이용 기간은 시작일 전날 14:00 KST 전까지만 전액 취소할 수 있다.

#### 모든 해지·시작 취소 요청의 공통 확인

- 고객의 해지·시작 취소 요청을 처리할 때 해당 구독에 `처리 중` 결제 거래가 하나라도 있으면 요청을 확정하지 않는다. 여기에는 자동결제 요청과 원 결제 취소 요청의 `처리 중` 거래가 모두 포함된다.
- 외부 응답으로 모든 `처리 중` 거래의 상태가 확정된 뒤에만 고객이 다시 요청할 수 있다. 결제 성공 뒤에는 아래의 다음 이용 기간 전액 취소 조건을, 09:00 실패 뒤에는 정기결제 재시도 중 해지 조건을 적용한다.
- 외부 응답을 끝내 받지 못한 거래는 `처리 중`으로 남는다. 다만 첫 구독 결제 POST의 결과가 불명확한 바로 그 요청 안에서는 같은 `paymentId`로 외부 결제 단건 조회를 한 번만 수행할 수 있다. 그 조회로도 결과를 확정하지 못하면 자동 결과 조회·자동 해지·자동 환불은 현재 MVP에서 제공하지 않는다.

#### 시작 예정 구독을 취소하는 경우

- 첫 구독의 **대상 첫 이용 기간**은 시작일 전날 `14:00:00 KST`보다 이전에 서버가 취소 요청을 접수하고, 대상 기간 주문 중 전달 완료 주문이 하나도 없을 때만 전액 취소할 수 있다. `14:00:00 KST`부터는 취소·환불 요청을 거절한다.
- 요청 접수 시각이 전날 14:00 전이면, 외부 원 결제 취소 응답이 14:00 후에 도착하더라도 이미 시작한 취소 처리는 계속한다.
- 조건을 통과하면 첫 이용 기간에 배분된 결제금액을 전액 취소하고 구독·첫 이용 기간·주문을 `시작 취소`로 바꾼다. 첫 이용 기간 금액이 최초 결제와 설정 변경 추가 결제 등 여러 원 결제에 나뉘어 있으면 `POL-PAYMENT-012`의 순서에 따라 모두 취소한다.
- 대상 첫 이용 기간 주문 중 하나라도 `전달 완료`가 된 뒤에는 시작 취소를 허용하지 않는다. 과거 이용 기간의 전달 완료 여부는 이 판단에 사용하지 않는다.
- 첫 결제에 30% 할인이 적용되었다면 시작 취소로 결제를 전액 취소하더라도 할인 사용 이력은 복구하지 않는다.

#### 다음 이용 기간의 결제가 완료된 경우

- 결제 성공한 **대상 다음 이용 기간**은 시작일 전날 `14:00:00 KST`보다 이전에 서버가 해지 요청을 접수하고, 대상 기간 주문 중 전달 완료 주문이 하나도 없을 때만 전액 취소할 수 있다. `14:00:00 KST`부터는 해당 기간의 취소·전액 환불 요청을 거절한다.
- 조건을 통과하면 해당 이용 기간 주문들에 배분된 하나 이상의 원 결제 금액을 모두 취소한다. 필요한 모든 취소에 성공한 경우에만 해지를 확정하고, 환불 대상인 다음 이용 기간과 그 주문은 `시작 취소`, 현재 구독은 `해지 예정`으로 바꾼다. 이때 시작 취소 사유는 `다음 기간 전액 취소`로 기록한다.
- 대상 다음 이용 기간 주문 중 하나라도 `전달 완료`가 된 뒤에는 해당 기간의 취소·전액 환불을 허용하지 않는다. 과거 이용 기간의 전달 완료 여부는 이 판단에 사용하지 않는다.
- 전날 14:00 이후에는 해당 요청 자체를 거절한다. 고객은 대상 다음 이용 기간이 실제로 시작한 뒤 일반 해지를 새로 신청할 수 있다.

#### 정기결제가 완료되지 않은 경우

- 09:00 정기결제의 실패 응답을 받은 뒤 13:00 재시도를 기다리는 중에 고객이 해지하면 재시도를 진행하지 않는다. 응답 전 결제 거래가 `처리 중`인 동안에는 해지를 확정하지 않는다.
- 현재 이용 기간은 마지막 날까지 유지하고 다음 이용 기간은 시작하지 않는다.
- 구독은 `해지 예정`, 미리 생성한 다음 이용 기간과 주문은 `시작 취소`, 결제 거래는 `재시도 중단`으로 확정한다.
- `시작 취소`는 첫 구독 취소와 공통으로 사용하되, 이 경우의 취소 사유는 `정기결제 재시도 중 해지`로 구분한다. 첫 구독 시작 취소와 달리 성공한 다음 기간 결제가 없으므로 환불은 발생하지 않는다.
- 13:00 재시도도 실패하면 다음 이용 기간은 시작하지 않으며 현재 이용 기간 종료 뒤 종료 처리만 진행한다.

#### 시작 취소 사유와 환불의 관계

이용 기간은 `시작 취소` 상태를 한 번만 가지며, 시작 취소 사유와 환불은 아래처럼 연결한다.

| 시작 취소 사유 | 환불 |
|---|---|
| 첫 구독 시작 취소 | `시작 예정 취소` 환불 |
| 정기결제 재시도 중 해지 | 환불 없음 |
| 다음 기간 전액 취소 | `다음 기간 전액 취소` 환불 |

- `다음 기간 전액 취소`는 이용 기간 상태가 아니라, 시작 취소된 다음 이용 기간에 연결되는 환불의 업무 구분이다.
- 같은 이용 기간에는 `시작 예정 취소` 환불과 `다음 기간 전액 취소` 환불을 함께 만들지 않는다.

#### 조건을 충족하지 못하면

- 전날 14:00 이후 요청, 대상 이용 기간 주문의 전달 완료, 또는 해당 구독의 `처리 중` 결제 거래가 있으면 해지·시작 취소를 확정하지 않고 현재 상태를 유지한다.
- 첫 취소부터 실패하여 결제금액을 전혀 환불하지 못하면 해지를 확정하지 않고 기존 구독을 유지한다.
- 일부 원 결제만 취소되면 성공한 취소는 유지하고 환불 상태를 `확인 필요`로 둔다. 성공·실패 내역과 미처리 금액은 보존하지만 현재 프로젝트에서는 추가 처리하지 않으며, 해지와 다음 이용 기간 취소를 완료로 확정하지 않는다.
- 첫 취소부터 실패한 경우 고객에게 구독이 해지되지 않았음을 알리며, 고객이 같은 해지를 다시 명시적으로 요청하면 기존 환불과 기존 원 결제 취소 결제 거래를 재사용한다. 부분 성공 이후의 추가 처리와 완료 기능은 현재 프로젝트 범위에 포함하지 않는다.

#### 실제 종료

- `해지 예정` 구독은 현재 `진행 중` 이용 기간의 마지막 날까지 유지한다.
- 현재 이용 기간이 끝난 다음 날 `00:00 KST` 이후 종료 처리에서 마지막 이용 기간을 `종료`, 구독을 `종료`로 같은 로컬 트랜잭션에서 변경하고 구독 상태 이력을 추가한다.
- 실제 종료가 확정된 뒤 Auth `INACTIVE`와 Customer `SUBSCRIPTION_ENDED` Event를 발행한다.

#### 예시

- 첫 배송 전날 13:59:59에 시작 예정 구독의 취소 요청을 서버가 접수하고 대상 첫 이용 기간 주문이 전달 완료되지 않았다면 전액 취소를 시작한다. 외부 취소 응답이 14:00 후에 도착해도 계속 처리한다.
- 첫 배송 전날 14:00:00 또는 그 이후에 취소를 요청하면, 대상 주문이 아직 전달 완료되지 않았더라도 취소·환불을 거절한다.
- 현재 이용 기간 마지막 날 09:00에 다음 기간 결제가 성공한 뒤 13:30에 해지 요청을 접수하면 대상 다음 이용 기간을 전액 취소할 수 있다. 14:00부터는 같은 요청을 거절하고, 15:00에는 다음 날 주문을 전달할 수 있다.
- 대상 다음 이용 기간 주문이 전달 완료된 뒤에는 전날 14:00 전이라는 가정과 무관하게 해당 기간의 취소·전액 환불을 허용하지 않는다.
- 09:00 정기결제 요청의 외부 응답을 기다리는 동안에는 해지를 확정하지 않는다. 실패 응답 뒤 13:00 전이면 재시도 중단 해지를, 성공 응답 뒤 전날 14:00 전이면 다음 이용 기간 전액 취소를 다시 요청할 수 있다.

### POL-SUBSCRIPTION-015 — 회원 탈퇴와 구독 해지 경계

- 마지막 확정일: 2026-08-23
- 적용 대상: 구독 해지 또는 회원 탈퇴를 요청하는 고객
- 정책 내용: 구독 해지는 구독 서비스가 처리하고, 회원 탈퇴는 인증 서비스가 처리한다. 인증 서비스는 구독 해지·환불을 대신 실행하거나, 회원 탈퇴 과정에서 구독 상태를 강제로 바꾸지 않는다.

#### 실제 이용이 남아 있는 경우

- `시작 예정`, `이용 중`, `해지 예정` 구독은 결제가 성공한 실제 구독이므로 인증 서비스 기준 `ACTIVE`를 유지한다.
- `해지 예정`은 다음 자동 갱신을 중단했을 뿐 현재 이용 기간이 끝난 상태가 아니다. 따라서 고객은 구독 해지를 신청했더라도 실제 이용 기간이 종료되기 전에는 회원 탈퇴할 수 없다.
- 현재 이용 기간이 실제로 끝나 구독이 `종료`가 되면 인증 서비스 기준 `INACTIVE`로 바뀌고, 인증 서비스가 이를 반영한 뒤에만 회원 탈퇴할 수 있다.

#### 첫 결제 대기 중인 경우

- `확정 대기`와 첫 결제 실패 구독은 아직 결제 성공 전이므로 인증 서비스 기준 `INACTIVE`로 본다.
- 이 기간에는 회원 탈퇴가 먼저 완료된 뒤 PG 결제가 늦게 성공할 수 있다. 현재 MVP에서는 이 경우 회원 탈퇴 사실을 근거로 자동 취소·자동 환불·자동 주문 무효화·자동 배송 중단·자동 계정 복구를 하지 않는다.
- 이 예외는 정상 업무로 인정하는 것이 아니라, 자동 보상 처리를 현재 MVP 범위에서 제외한 Known Limitation이다.

### POL-ORDER-002 — 구독 설정 변경의 주문 적용

- 마지막 확정일: 2026-09-06
- 적용 대상: 구독 설정을 변경한 고객의 주문
- 정책 내용: 구독 설정 변경 적용일 전의 주문은 기존 구독 설정을 유지한다. 변경 적용일부터의 실제 배송일에는 변경된 플랜·배송 요일·배송 요일별 인원수·배송지·배송 시간대를 반영한다.

#### 핵심 제약

- 배송 요일을 변경하면 변경 적용일부터 제외된 요일에는 주문이 없고 새로 선택한 요일에는 주문이 생긴다.
- 결제·환불 전에 새 설정에 따른 주문을 `변경 대기`로 먼저 생성하고 기존 유효 주문은 그대로 유지한다.
- 결제·환불 성공 또는 차액 없음이 확정되면 기존 주문을 비활성화하고 새 주문을 유효로 바꾸는 작업을 하나의 로컬 트랜잭션에서 처리한다.
- 추가 결제가 실패하거나 여러 원 결제 환불의 첫 취소부터 실패하면 새 주문은 `변경 미적용`으로 바꾸고 기존 주문은 유효 상태를 유지한다.
- 여러 원 결제 환불 중 일부만 성공하면 새 주문은 `변경 대기`, 기존 주문은 `유효` 상태를 유지하고 모든 취소가 성공하기 전에는 주문 교체를 확정하지 않는다.
- 설정 변경 적용일 계산과 다음 날 주문만 전달하는 규칙에 따라, 이미 `전달 완료`된 주문은 설정 변경 대상에 포함하지 않는다.
- 같은 배송일의 새 변경 주문은 같은 구독·이용 기간·배송일에서 현재 `유효`이고 아직 전달 완료되지 않은 주문을 대체 대상으로 참조한다. 개정 순번이 더 크더라도 `변경 미적용` 주문은 대체 대상으로 사용하지 않는다.
- 실패한 여러 변경 주문은 같은 기존 유효 주문을 대체 대상으로 참조할 수 있지만, 그 기존 주문을 실제로 대체하여 `유효`가 된 새 주문은 최대 한 건이다.
- 설정에서 삭제된 배송일의 기존 주문과 다른 배송일에 새로 추가된 주문은 주문 계보상 대체 관계로 연결하지 않는다. 신규 배송일 주문에는 대체 대상이 없지만, 설정 변경 성공 확정 시 기존 주문 묶음의 남은 결제금액을 새 주문 묶음에 재배분할 수 있다.
- 주문 개정 순번은 같은 배송일 주문의 생성 순서를, 대체 대상 주문 관계는 실제 변경 대상 계보를 나타내므로 함께 유지한다.

#### 예시

화요일 15:00에 구독 설정을 변경하면 목요일부터 변경된 설정을 반영한다. 수요일 주문은 기존 설정을 유지하고, 목요일 이후 실제 배송일의 주문부터 새 설정을 적용한다.

### POL-ORDER-003 — 생성된 주문의 내용 유지

- 마지막 확정일: 2026-08-17
- 적용 대상: 생성된 모든 주문
- 정책 내용: 주문에는 생성 당시 적용된 플랜·도시락 단가·해당 배송 요일의 인원수·도시락 금액·배송비·할인금액·실제 배분금액·배송일·배송지·배송 시간대·배달 방식 문자열 코드·`OTHER`의 고객 직접 입력 문자열을 그대로 유지한다. 이후 가격·구독 설정이나 배송지를 변경해도 이미 생성된 주문의 내용은 바뀌지 않는다.

#### 예시

8월 10일 주문이 인원수 2명과 배달 방식 `DIRECT`로 생성된 뒤 가격·구독 설정이나 배송지의 배달 방식을 변경해도, 해당 주문은 생성 당시 금액과 내용을 유지한다.

### POL-ORDER-004 — 개별 주문 취소 제한

- 마지막 확정일: 2026-08-18
- 적용 대상: 구독을 이용 중인 고객
- 정책 내용: 고객은 생성된 주문 한 건만 따로 취소하거나 환불받을 수 없으며, 개별 주문의 배송일을 다른 날짜로 옮길 수 없다.

#### 핵심 제약

- 플랜·배송 요일·요일별 인원수·배송지·배송 시간대 변경은 개별 주문 변경이 아니라 구독 설정 변경으로 처리한다.
- 고객의 개별 주문 취소 요청과 배달·배송 서비스가 환불 대상으로 확정한 배송 건 처리는 서로 다른 경우다. 서비스가 확정한 배송 건은 `POL-ORDER-008`에 따라 구독 서비스가 환불한다.

#### 예시

월요일·수요일·금요일 주문 중 수요일 주문만 취소하거나 목요일로 옮기는 것은 허용하지 않는다.
